# 中文来源工作手册（方法论，不绑定任何服务）

本文件只描述检索与引文定位的方法，不要求安装特定服务；实际可用的工具以当前 runtime 已授权的搜索/浏览/MCP 能力为准。能力缺失时按 profile 降级并在 manifest 中披露覆盖限制。

## 来源分层与独立性

| 层级 | 典型来源 | 用途 |
|---|---|---|
| T1 官方 | 监管机构（证监会、央行、工信部）、交易所/巨潮资讯网披露、公司官网与招股书、国家标准全文 | 高影响 claim 的首选 |
| T2 权威二手 | 统计年鉴、行业协会报告、头部的券商/咨询公开摘要 | 交叉验证 |
| T3 社区与媒体 | 知乎专栏、微信公众号、36氪、虎嗅、V2EX | 线索发现、用户反馈；不当事实终点 |
| T4 UGC | 小红书、微博、短视频评论 | 仅用于"真实用户声音"类证据，标注低置信 |

同一篇通稿的多平台转载只算一个 `independence_group`；识别转载链（相同导语、相同数字、时间接近）后在 sources.jsonl 合并登记。

## 引文定位要点（影响 verify_evidence.py 的回贴成功率）

- **公众号文章**：正文常被分成多个 `<section>` 块且段落间有插入元素。摘录时引用**单一段落内**的连续文字，不要跨段；回贴核验按规范化文本匹配，跨段省略号引文可能被判 `mismatch`。
- **知乎**：优先引用回答正文而非折叠区；赞同数会变化，不要把赞同数写进 claim。
- **法规/标准**：引用条款号 + 原文（如 "第十四条"），GB 标准优先引用官方全文平台的页码/章节。
- **中文标点**：全角标点、引号变体、段落内的全角空格都会被核验器规范化，无需手工处理；但**不要**在摘录中加入自己的括号注解，注解放进 evidence 的 `location` 或单独字段。
- **PDF（招股书、年报、判决书）**：当前核验器对 PDF 标记为 `unverifiable`。摘录时给出页码，并在 evidence 中注明 "pdf, page N"；有条件时同时登记该 PDF 的官方 HTML 版本作为第二来源。

## 时效与存档

- 中文网页内容变更频繁：`retrieved_at` 必填；高影响 claim 建议在 sources.jsonl 记录 `archive_url`（如 web.archive.org 快照）。
- 财报与公告类来源以**披露日期**为准（巨潮/交易所页面的公告日期），不是媒体转载日期。
- 政策类结论必须区分"发布稿"与"征求意见稿"，version 写进 evidence 的适用范围。

## 检索策略模板

每个子问题生成四类查询时，中文场景额外覆盖：

1. 定义类：`"<术语> 官方定义"`、`"<术语> 国标"`、`"site:gov.cn <术语>"`（runtime 支持时）。
2. 直接证据：`"<主体> 公告 <年份>"`、`"<主体> 招股说明书 <章节>"`。
3. 反方/风险：`"<主体> 处罚"`、`"<主体> 维权"`、`"<产品> 踩坑"`、`"<产品> 缺点"`。
4. 时间变化：`"<主题> 2024"` 与 `"<主题> 2026"` 对比，识别口径变化。

搜索摘要只用于筛选；正式 evidence 必须来自打开后的原文。
